隐私声明

本声明适用于 kinfey 发布的 OfficeAgent 助手及本支持网站。组织在启用前应确认实际部署、授权和保留策略符合自身要求。

1. 谁负责服务

发布者与维护者为 kinfey。使用组织的管理员负责其租户内的身份、访问范围、数据治理、许可证和保留策略。本声明不替代组织自己的隐私通知或 Microsoft 服务协议，也不表示助手已经通过任何特定合规认证。

2. 助手处理哪些数据

为完成获授权的请求，助手可能处理 Teams 私聊输入、身份及会话标识、被明确委派的邮件内容和信封信息、日历事件、参会人地址、忙闲信息，以及操作预览、确认状态和服务回执。

这些数据用于理解请求、提供摘要或草稿、协调会议，以及验证操作是否由正确的经理在正确会话中批准。没有相应授权时，助手不应读取数据或执行操作。

3. 数据在哪里处理

请求及完成任务所需的内容会交由部署中配置的 Microsoft Foundry 模型、Work IQ 和相关 Microsoft 365 服务处理。具体区域、服务条款、审计和数据保护措施由组织选用的服务与配置决定。

助手以自己的 agent-user 身份访问已委派资源，不要求经理提供密码。此静态支持网站不接收、存储或展示助手的邮箱内容与办公会话。

4. 存储与保留

当前实现最多保留最近 12 条用户与助手消息作为会话上下文。待审批状态可能包含操作正文、收件人或会议详情；确认码 10 分钟有效，已消费确认码的去重标记按 1 天保留配置写入平台状态存储。

确认码失效不等于所有会话记录或备份已经删除。其他会话状态、Microsoft 365 数据、审计日志及备份的实际保留期限由平台和组织策略决定。请联系组织管理员核实或提出删除请求。

5. 日志与公开支持

应用默认关闭生成式内容遥测捕获，不主动把邮件正文、聊天文本或令牌写入自定义业务日志。底层服务仍可能按组织配置产生必要的运维、安全和审计记录。

本网站没有分析或营销追踪脚本，也没有上传表单。GitHub Pages 托管基础设施可能处理常规访问日志，具体见 GitHub 隐私声明。公开 Issues 的内容可被公众看到，不得提交任何秘密或办公数据。

6. 你的选择与联系渠道

可以不发送敏感材料、不批准待审操作，或要求组织管理员撤销邮箱和日历委派、禁用助手实例及处理相关数据请求。只有符合授权要求的经理私聊才应进入办公处理流程。

一般产品隐私问题可通过 脱敏的 GitHub Issue 联系维护者。涉及身份核验、组织数据或安全事件时，应使用组织内部的管理员渠道，不要公开个人资料或内容。

7. 声明更新

功能、服务依赖或数据处理方式发生变化时，本声明可能更新。组织应在启用新版本前重新审阅；重大变更还需遵循其内部通知和审批流程。
